# 🧾 오답노트 — 호텔 대실 (프로그래머스 Lv.2)

### 📅 풀이 일자

2025-11-23

---

## 📌 문제 요약

여러 예약(time intervals)이 주어져 있을 때, 각 예약 종료 뒤 **10분의 청소시간**이 포함된다고 가정하고 필요한 **최소 객실 수**를 계산하는 문제이다.  
실제 방을 생성하거나 방 번호를 추적할 필요 없이, **동시에 몇 개의 방이 필요했는지(최대 동시 점유량)**만 계산하면 해결할 수 있다.

---

## 💀 나의 초기 접근 & 실패 원인

```text
- room 배열에 각 방의 endTime을 저장
- 새로운 예약 시작시간이 기존 endTime보다 크거나 같은 방이 있는지 선형 탐색
- 선형 탐색이 반복될수록 비용 증가 → O(n²)
```

### ❌ 문제점

| 항목        | 내용                                      | 영향                      |
| ----------- | ----------------------------------------- | ------------------------- |
| 시간 복잡도 | 매 예약마다 room 전체 순회                | 최악 O(n²) 가능           |
| 사고 모델   | 방을 “ID가 있는 실제 객체”로 모델링       | 문제 본질과 불필요한 결합 |
| 목표 불일치 | 필요한 건 방 번호가 아니라 “최대 동시 수” | 단순한 관점 놓침          |

---

## ✅ 올바른 사고 전환

> **핵심:** 방은 “객체”가 아니라 **비는 시간(end)**을 가지는 **시간 슬롯(slot)** 이다.  
> 방 ID는 중요하지 않으며, 우리가 필요한 건 **동시에 몇 개의 end 슬롯이 겹치는가** 뿐이다.

### 1) 시작/종료 시간 분리

- 모든 시작(start) 시간을 배열 `STARTS`
- 모든 종료(end+10) 시간을 배열 `ENDS`
- 두 배열을 각각 정렬

### 2) 두 포인터 방식으로 슬롯 충돌 계산

- `start < ENDS[endIdx]`  
  → 가장 빨리 비는 방보다 먼저 시작 → **새 방 필요**

- `start >= ENDS[endIdx]`  
  → 가장 빨리 비는 방 재사용 가능 → `endIdx++`

➡️ 방 ID 없이도 **슬롯 충돌 수 = 필요한 최소 방 개수**

---

## 🧠 풀이 구조(코드 없이 로직만)

1. `"HH:MM"` → 분 단위 변환 함수 작성
2. 예약 리스트에서 STARTS, ENDS 배열 생성(END에 +10 적용)
3. STARTS, ENDS를 각각 정렬
4. `rooms = 0`, `endIdx = 0` 초기화
5. STARTS 순회
   - `start < ENDS[endIdx]` → `rooms++`
   - else → `endIdx++`
6. rooms 반환

**시간 복잡도:** O(n log n)  
**공간 복잡도:** O(n)

## 🧩 디버깅 포인트

- END 배열이 START보다 먼저 소진되는 경우 처리
- START와 END가 같은 시각에 만나는 edge-case
- 하나의 예약만 있을 때 rooms=1 동작 여부
- END 배열 접근 시 out-of-range 방지

## ⚖️ 대안 비교

| 접근 방식               | 장점                 | 단점                           | 비고            |
| ----------------------- | -------------------- | ------------------------------ | --------------- |
| room[] 선형 탐색        | 구현 직관적          | O(n²) 위험                     | 초기 접근 방식  |
| **두 포인터(권장)**     | O(n log n), 단순     | 방 ID가 없어 다소 낯설 수 있음 | 최적 해법       |
| 최소 힙(priority queue) | 이론적으로 가장 정석 | JS 구현 비용 높음              | 면접용으로 적합 |

---

## 🧠 기억 메모(재발 방지)

- 방은 **객체가 아니라 slot(비는 시간)** 이다.
- 스케줄링 문제는 항상 “가장 빨리 끝나는 시간”이 핵심 포인트.
- 시작/종료 시간을 분리해 정렬하면 복잡도가 크게 떨어진다.
- 방 번호에 집착하면 알고리즘의 본질이 흐려진다.
